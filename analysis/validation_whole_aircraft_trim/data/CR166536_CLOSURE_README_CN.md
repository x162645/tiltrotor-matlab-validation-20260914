## 这次纠正了什么

1. 旧机身滚转力矩表 `l_beta` 的单位误写为 ft²，现按正文输入定义和力矩方程更正为 ft³，数值不变。
2. 4-VIII 的 `Cm_WP` 原表印“1/rad”，正文 `M=qScCm` 则明确要求无量纲。接口采用无量纲，原文单位仍完整保留，没有乘除 57.3。
3. 4-XV 的短舱干扰阻力参数虽然名称含 coefficient，方程所需单位是 ft²；4-XVI 的输入是短舱/桨帽入射角，不是机身侧滑角。
4. 平尾侧滑导数为 1/deg；垂尾速率修正作用于带帽的归一化速率，不能直接乘 rad/s 的机体速率。
5. 高清复核确认垂尾侧洗迎角端点为 `<=-10°`、`>=28°`；4-XI 为 `|alpha|<=8°`、`8<alpha<=25°`。原先模糊的不等号已更正。
6. 5-II、6-II 低马赫数列明确引用 5-I、6-I，适用的引用角度范围为 -180° 至 180°，不是只限于次表显示的 -40° 至 40°。

## 仍须保留的原报告差异

这是原文内部差异，不是看不清的数字：机翼弦长在 B12 为 5.255 ft、B31 为 5.225 ft；垂尾单片面积在 B12 为 25.25 ft²、B69 为 20.25 ft²；B69 还把两片垂尾的水线写成一正一负，而侧线同号。数据包保留各自来源，尚未据此生成新的整机几何。4-XI 脚注也没有明确给出 alpha<-8° 的副翼效率扩展，不能擅自套用正迎角衰减规律。

原文少数不对称或异常数值（如垂尾旋翼侧洗因子 -0.5）均保留。完整数字化不等于证明这些源模型参数处处正确。

## 运行与接口

Python 读取和检查只需标准库；绘图另需 matplotlib 和中文字体。

在本目录运行：

```text
python cr166536_tables.py
python check_cr166536_digitization.py
python plot_cr166536_source_tables.py
```

在仓库根目录运行时，在文件名前加 `analysis/validation_whole_aircraft_trim/data/`。

```python
from cr166536_tables import TableDatabase

db = TableDatabase()
# 查询垂尾原表节点，保留完整原行和出处。
rows = db.select('6-VIII', row_key=40, col_key=0)
assert rows[0]['value'] == -0.5

# 读取指定构型的平尾升力；返回值注明源节点、插值或跨表引用。
result = db.curve('5-II', 'alpha_deg', 10,
                  elevator_deg=0, mach_label='0-0.2')
print(result)
```

`select()` 支持全部表的原坐标标签。`curve()` 支持其余坐标固定后的一维数值轴；拒绝表外外推、原文未定义、混合构型和区间/合并标签轴。区间马赫数、襟翼组合、正负角映射和多维 GTRS 调度仍要由各子系统明确实现，不能由通用读取器猜测。

本轮源页采用 PDF 渲染后人工视觉抄录；机翼选定 7 页的 451 条记录进行了第二次逐格视觉复核，另核查尾翼异常值、单位与边界。程序通过全部 9 组检查，包括表号/页码/缺失状态、重复节点冲突、17 处源图数值锚点、引用全角域和域外拒绝。自动检查覆盖结构与读取行为，不能代替原文逐格核查或外部验模。

实际表格检查运行于 Windows、Python 3.12（bundled runtime）；绘图使用现有 Python 3.8.3、matplotlib 3.7.5 与 Microsoft YaHei。首次 bundled Python 绘图因未安装 matplotlib 失败，随后使用已安装绘图库的 Python 3.8 完成，图像已实际查看，中文显示正常。本次没有执行 MATLAB 或新的整机仿真。
